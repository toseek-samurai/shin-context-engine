# v2.0.5-dev.101

Preview candidate. Each platform is published after its source and exact archive
pass qualification in CI.

- Rebuild managed indexes, source readers and qualification state from current project sources for each new kit, including same-Core updates. Preserve enrollment, project-owned profiles, approvals, client settings and history.
- Keep pending and blocked enrolled projects visible during installation and recovery. Rebuild owned derived state automatically; show cause-specific recovery actions in the compact Monitor and TUI, with EN/RU guidance.
- Remove historical generator allowlists and Core-version compatibility ladders. Installation keeps its transactional recovery and source/authority fences instead of depending on earlier derived formats.
- Reuse bounded compiler-cache artifacts across release tags only after the producing component passes its source and exact-package gates. Missing or rejected caches fall back to compilation; platform publication stays independent.
- Link Core/Observer version metadata from separate generated source files and preserve unchanged generated headers, avoiding widespread recompilation for version-only changes.
- Use MSVC with Ninja Multi-Config and sccache in Windows CI, build the existing Core smoke suite's complete executable dependencies, and retain the interactive Visual Studio presets and desktop/MSI qualification.
- Stabilize interrupted refresh invalidation handling and the deterministic FIFO admission fixture without relaxing runtime timeouts or safety checks.
- Keep a newly spawned service alive through the brief bound-before-listen socket window; retry only its startup status probe within the existing deadline, without replaying user requests or hiding authority/protocol failures.

Build optimization tracks #33. Hosted timing and native Windows execution remain subject to the release CI; local macOS source validation does not qualify a public archive.

After updating, projects may show Preparing while the new kit rebuilds their
derived data. Project-owned profiles, approvals and client settings stay in place.

Core is `2.0.5-dev.20`. Observer, CLI, MCP, Monitor and Updater are `2.0.5-dev.101`.
