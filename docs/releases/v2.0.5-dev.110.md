# v2.0.5-dev.110

Preview candidate. Each platform is published after its source and exact archive
pass qualification in CI.

- Separate Windows notification-area quick status from the full Monitor. The
  quick panel anchors to the icon and offers native keyboard-accessible actions.
  The desktop uses a standard movable/resizable Windows frame, taskbar/Alt+Tab,
  minimize/maximize, retained placement and close-to-tray behavior. Opening it
  again restores the existing instance; sign-in startup stays in the background.
- Keep the desktop open across focus changes, settings and update operations.
  Return keyboard focus to the desktop after quick actions, dismiss quick status
  before its context menu, and stop graphics work while minimized or hidden.
- Enable system common-control visual styles and the supported system dark
  frame. Exercise actual HWND lifecycle, placement/DPI bounds, EN/RU rendering,
  native keyboard actions and a real second-process handoff in qualification.
  An occupied qualification fixture fails instead of accepting stale success.
- Preserve the current UI profile's source-file budget across Windows checkouts
  by keeping the shared Monitor header in canonical LF, without changing its code
  or relaxing retrieval expectations and limits.
- Include dev.109's live per-agent MCP project catalogs and connection states.
  Existing static connections need one host reload/reconnect to adopt that
  contract; subsequent allowed project additions need no agent restart.
- Fix the Windows connection-helper include scope from dev.109 so the desktop
  target can compile with the shared connection-state captions.
- Update the Windows client fixture for strict settings reads: refuse hardlinks
  during preview and refuse a reviewed file replaced by a hardlink before apply.

Core remains `2.0.5-dev.22`. Observer, CLI, MCP, Monitor and Updater are
`2.0.5-dev.110`. Generator remains `shin-generator-v24-objective-cpp`.

Native and render checks do not replace physical multi-monitor/DPI or assistive
technology verification. This release does not change macOS window behavior.
