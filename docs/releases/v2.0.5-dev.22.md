This preview reduces cold-reader admission delays and keeps background preparation moving after a short refusal.

- A pending read wakes an idle project's normal background qualification. Reader demand receives priority between refreshes, alternating with due background work.
- Reader admission waits at most five seconds within the existing request budget. If preparation is still pending, the call returns explicit `project-updating`; qualified context is never replaced with stale results.
- A bounded scheduling hint remains after the initial caller leaves, so preparation can finish when an unrelated refresh releases the publisher. Internal retries do not extend it.
- Existing publication authority, source verification, failure backoff, single-refresh scheduling and resource limits remain enforced.
- Session/model guidance explains missing per-call model metadata. Supplied model labels remain caller-reported; this release does not infer a model from token totals or shared client defaults.

Disposable regression fixtures cover idle-reader recovery within three seconds, the five-second admission bound, and background preparation after a refused read. These fixtures establish behavior, not a latency guarantee for every project or workload. See [#18](https://github.com/toseek-samurai/shin-context-engine/issues/18).
