This preview fixes stale update offers in Shin Monitor.

- Manual update checks and the update-available action fetch the current release before displaying the installation confirmation, even when a previous check was recent.
- The confirmation pins the exact release shown to the user. A newer publication still requires another explicit review; the installer never silently substitutes it.
- Monitor clears a rejected stale offer and shows the native failure detail. Changed-offer recovery instructions are available in EN/RU.
- Background check intervals, concurrent-check coalescing, revision approval, archive checksums and native installation safeguards remain enforced. Installation is never retried automatically.

The regression harness exercises the real Monitor actions without network access, installation or user preferences. It reproduces the stale offer on the previous implementation and verifies fresh manual/menu offers, concurrent-check bounds and diagnostics in both languages. See [#20](https://github.com/toseek-samurai/shin-context-engine/issues/20).

macOS 15 or newer, Apple Silicon. Ad-hoc signed preview; Developer ID signing and notarization are not included. Core remains 2.0.5-dev.3; Observer/CLI/MCP are 2.0.5-dev.25 and Monitor is build 49.

In an older Monitor, choose **Check for updates** again and confirm that the offered version is **2.0.5-dev.25** before installing. Alternatively:

```sh
curl -fsSL https://github.com/toseek-samurai/shin-context-engine/releases/download/v2.0.5-dev.25/install.sh | sh
```

Reconnect persistent MCP clients after updating. Project authority, client settings and history stay in their existing data home. This release is published only after its matching CI matrix and exact macOS artifact qualification pass.
