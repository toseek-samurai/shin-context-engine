This preview fixes premature rollback when an update starts a service with several registered projects.

- Service startup follows actual admission progress instead of applying one 60-second deadline to the entire registry. The first admission or readiness outcome of each selected project renews a 60-second no-progress budget, with a five-minute absolute cap.
- Repeated status replies, changed snapshots and unrelated projects cannot extend the wait. A service instance change is refused. Resident and standby readiness, enrollment errors, installation ownership and rollback safeguards remain enforced.
- Expiration of this startup wait is reported as `service-enrollment-timeout`, rather than a misleading `service-request-cancelled`.

The regression uses virtual time to cover successful serial admission beyond 60 seconds, stalled progress, the absolute cap and preserved readiness/refusal behavior. Native service/supervision and disposable installation/update/rollback suites also pass. EN/RU progress-window tests wait for the actual displayed stage and byte state within their existing five-second bound, avoiding a race between cold AppKit startup and a fixed capture delay. See [#22](https://github.com/toseek-samurai/shin-context-engine/issues/22).

macOS 15 or newer, Apple Silicon. Ad-hoc signed preview; Developer ID signing and notarization are not included. Core remains 2.0.5-dev.3; Observer/CLI/MCP are 2.0.5-dev.28 and Monitor is build 52.

Choose **Check for updates** in Monitor and confirm that the offered version is **2.0.5-dev.28** before installing. If a previous attempt rolled back, review its saved outcome in **Last update result…** and acknowledge the verified result before retrying. An incomplete native recovery must be resolved first.

The native progress window is supplied by the installed helper. Updates started from dev.25 or earlier still use the older updater; progress becomes available for subsequent updates started from this kit.
