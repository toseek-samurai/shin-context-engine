This preview fixes retrying an update after rollback when the previous service cannot admit a registered project.

- The installer independently checks the previous service using its exact Observer/Core versions. A known quality or temporary enrollment refusal can describe an already unready project during a supported Core patch transition. Unknown roots and hard registry, identity, engine or integrity errors still stop recovery; every project must qualify under the target kit before success.
- Failed project qualification retains the affected project's opaque hash and bounded readiness reasons, including source changes during activation. Additional diagnostic details remain explicitly marked when truncated.
- Monitor shows the visible project range and total in EN/RU and accessibility, so a short final page is clearly part of the full project list.

Local verification reproduces the refusal with real dev.28 and unchanged dev.32 executables, then completes rollback and retry with dev.33 extracted from the exact local ZIP. Both synthetic projects become ready while preserving registry, identity, publication authority, request history and refresh aggregates. Thirteen affected checks and all six exact-archive package-smoke stages pass. The matching Linux/macOS CI matrix and its exact archive must pass before publication. See [#16](https://github.com/toseek-samurai/shin-context-engine/issues/16).

macOS 15 or newer, Apple Silicon. Ad-hoc signed preview; Developer ID signing and notarization are not included. Core is 2.0.5-dev.4; Observer/CLI/MCP are 2.0.5-dev.33 and Monitor is build 57. Native Windows execution is not part of this preview's qualification.
