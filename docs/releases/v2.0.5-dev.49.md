# v2.0.5-dev.49

This preview restores live TUI charts when local telemetry grows and ships a
separate updater whose installation and recovery logic travels with the release.
It includes Core 2.0.5-dev.7 and the Unicode v23 index format.

- Large service-status replies retain a minute of live memory/concurrency samples
  and recent request timings before trimming bulky diagnostic history. Essential
  project health still takes priority; the 60-KiB response limit is unchanged.
  Only the response copy is shortened: collected history is preserved.
- TUI graphs show the last measured value, visible measurement count and actual
  time range. Sparse observations have visible markers. Idle timing windows,
  omitted data and disconnected observations have distinct explanations. Missing
  values, source gaps and unknown service-run boundaries never become invented
  zeroes or continuous curves. EN/RU and compact terminal captures are refreshed.
- Monitor, CLI and TUI download and verify the release's independent Updater
  through a bounded protocol before handing over installation. The fresh Updater
  owns full-kit validation, activation, rollback, its progress window and saved
  results. Status and acknowledgement remain available offline for a retained
  update outcome. The versioned install.sh also uses the fresh Updater.
- The TUI Updates view supports release checks, explicit installation
  confirmation, actual transfer/project progress and saved-result review.
  Monitor keeps its update-review window visible until the progress window takes
  over, including during live EN/RU switching.
- CI qualifies the separate Updater against the exact macOS kit and publishes
  both archives with their SHA-256 checksums and the versioned installer only
  after the Linux/macOS matrix and exact-archive checks pass.

Install through Monitor or the versioned installer after this preview is
published. Restart the terminal dashboard and persistent MCP clients afterwards
so their adapters match the service. Projects, profiles, grants and local history
remain owned by the existing installation. Desktop builds remain unsigned
previews without Developer ID notarization.

The dev.46 kit was used as a local installation baseline and was not published.

The dev.47 candidate was not published. Service integration checks now account
for explicitly reported cohort omissions in a bounded status reply, while still
checking live chart reserves, complete stored history and a small stop receipt.
The short-collision recovery check is separate from the independent-project
availability check, so unrelated work cannot spend its real 500 ms admission
budget. Product limits and the distinct recovery/expiry assertions are unchanged.

The dev.48 candidate was not published. Its macOS rerun passed the corrected
service suite but exposed writer contention in the live marker-approval test.
That test now checks that a busy writer leaves the grant unchanged, waits only
on this known refusal with one pinned SHA-256 revision, and still requires the
canonical reader to refresh after approval. Authority checks and product limits
are unchanged.
