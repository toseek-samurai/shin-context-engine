# v2.0.5-dev.53

This preview keeps projects using the default bootstrap route available while
their documentation is being edited. A broken local Markdown link becomes a
visible warning instead of blocking verified context retrieval.

- Local qualification accepts only known link-only `doctor` and `vacuum`
  failures. Index integrity, freshness, secrets, resource limits and other
  refusal conditions remain required. Strict Core audits and explicit permanent
  project profiles retain their quality gates.
- Monitor and the terminal show documentation warnings in EN/RU. Warning counts
  survive qualification reuse and clear after the corrected documentation passes
  its next refresh. Genuine bootstrap failures retain bounded gate diagnostics.
- Regression coverage checks automatic refresh with a missing document,
  repeated queries, warning removal and rejection of safety, access and output
  drift failures. Native UI fixtures cover five window sizes in both languages.

This preview also includes the changes from the unpublished dev.51 and dev.52
candidates:

- Monitor's Sessions tab presents a Sand journal with readable monospace text,
  UTC timestamps, opaque session IDs, icons and distinct outcome colors. The
  display is bounded to eight sessions and six events per session; stored
  history and totals retain their existing limits.
- Bounded service replies preserve the latest session before trimming history
  detail. Monitor and the terminal explain omitted session details accurately.
  The 60-KiB service response ceiling is unchanged.
- Core 2.0.5-dev.8 improves explanatory English and Russian queries. Verbs such
  as `work` in `how engines work with SQL` no longer hide relevant documents;
  literal, quoted and qualified identifier searches retain their terms.
- The README and CLI guide include the Sessions journal and native EN/RU
  screenshots rendered with independent synthetic data.

Update through Monitor's **Check for updates…** action. The independent Updater
shows progress while replacing the kit; projects, settings and history stay in
their recorded home. Reconnect persistent MCP clients after installation.
Desktop builds remain unsigned previews without Developer ID notarization.
