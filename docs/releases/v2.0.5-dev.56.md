# v2.0.5-dev.56

This preview fixes macOS Monitor termination with its standalone window open,
improves access from the menu bar, and introduces guarded Windows x64 ZIP/MSI
downloads alongside the macOS kit.

- Monitor closes its presentation before releasing the underlying model. Late
  AppKit window/popover notifications remain safe, including during handoff to
  the updater. Refusing to quit keeps the Monitor window available.
- Native regression checks cover actual process exit with a standalone window,
  fragmented updater acknowledgements and refused termination. The CLI harness
  uses disposable state instead of starting the installed Monitor workflow.
- The menu-bar icon keeps a fixed width when an update is available, preserving
  its accessibility label. Opening Monitor uses a standalone window when the
  status item cannot anchor a popover; focus, reopening and Compact view remain
  covered by EN/RU checks.
- Windows packages join the Linux/macOS source qualification workflow. Before
  publication, the exact ZIP/MSI payloads, inventories, hashes, component versions
  and source/run identity are verified. Runtime checks use a standard user with
  a private temporary directory; packaging reuses the tested build tree.

Core remains 2.0.5-dev.8. Windows targets x64 on local NTFS. Hosted Windows render
checks are explicitly headless; interactive notification-area and installed
lifecycle checks remain separate. Windows TUI, automatic client connection,
usage collection and in-app updating remain pending. See
[Windows support](../windows-desktop.md) for the current boundaries.

Existing macOS installations can update through Monitor. Projects, settings and
history stay in their recorded home; reconnect persistent MCP clients after
updating. The macOS kit requires macOS 15+ on Apple Silicon and remains an
ad-hoc-signed preview without Developer ID notarization.
