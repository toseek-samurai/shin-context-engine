# Project setup and freshness

Register a project with the installed service and choose its authorized agent
settings. Selecting a named Hermes configuration limits that connection to its
own grants. Use the configured kit and data home. Keep the actual project root
and returned snapshot together for every follow-up.

Discovery covers eligible text under the folder without a list of extensions.
Project `.gitignore` rules apply first. Root `.shinignore` rules may exclude or re-include eligible paths. Rules and source edits
are observed automatically. New kits rebuild registered folders under their
current discovery rules and preserve the selected agent settings.

When a project is preparing, use the useful query and its bounded readiness
wait. After a source race, use direct sources if necessary, then query the same
project for a fresh snapshot. Preserve real grant, revoked access, quarantine,
resource, integrity and freshness failures. Report a persistent refusal with
the project and safe reason code. An agent cannot approve a route change,
re-enroll a project or manually publish a managed index to clear a blocker.

Explicit standalone Core publication, profile selection and strict evaluation
are developer workflows with their own inputs and external outputs. Use the
selected Core contracts only when that workflow was requested.
